Resumo definitivo do PIM IV — TechLearn Academy
A TechLearn Academy será uma plataforma de cursos on-line de programação. Ela reunirá usuários, cursos, módulos, materiais, matrículas, avaliações, resultados e progresso em um único sistema.
A solução terá:
- um site responsivo;
- um aplicativo mobile;
- um programa desktop;
- uma API em C#;
- um banco SQL Server;
- quatro perfis: Aluno, Mentor, Gestor e Administrador;
- os mesmos dados e regras em todas as versões.
A aplicação web será desenvolvida primeiro. Depois, mobile e desktop utilizarão a mesma API já construída.
1. Definição oficial do projeto
Problema
Atualmente, cursos, materiais, matrículas, avaliações e resultados seriam controlados em planilhas, arquivos, links e mensagens separados.
Isso causa:
- informações duplicadas;
- dificuldade para encontrar materiais;
- correção manual demorada;
- dificuldade para controlar acessos;
- falta de acompanhamento do progresso;
- dificuldade para gestores e mentores acompanharem os alunos.
Solução
Construir uma plataforma integrada em que:
- o aluno estuda e acompanha seu desempenho;
- o mentor acompanha alunos e registra orientações;
- o gestor administra cursos e acompanha indicadores;
- o administrador controla usuários, perfis e acessos;
- todas as versões usam a mesma API e o mesmo banco.
Público-alvo
- estudantes;
- iniciantes em programação;
- autodidatas;
- pessoas em transição de carreira;
- profissionais procurando aperfeiçoamento;
- pessoas que precisam estudar em horários flexíveis.
Proposta de valor
Oferecer uma jornada de aprendizagem simples e organizada, reunindo em um único ambiente:
- cursos;
- módulos;
- materiais;
- matrículas;
- avaliações automáticas;
- resultados;
- progresso;
- acompanhamento de mentor.
2. Escopo oficial
O que estará no projeto
- cadastro de aluno;
- login;
- recuperação de senha por e-mail;
- controle por perfil;
- quatro perfis de usuário;
- gerenciamento de cursos;
- gerenciamento de módulos;
- materiais em PDF ou links;
- matrícula;
- acompanhamento dos cursos;
- avaliações objetivas;
- correção automática;
- nota de 0 a 10;
- percentual de acertos;
- situação de aprovação;
- progresso do aluno;
- acompanhamento de alunos pelo mentor;
- orientações do mentor;
- relatórios e indicadores para o gestor;
- gerenciamento de usuários pelo administrador;
- acessibilidade básica;
- web, mobile e desktop;
- API REST;
- SQL Server;
- plano de nuvem e DevOps;
- gerenciamento ágil.
O que ficará fora
- chat em tempo real;
- pagamentos dentro do sistema;
- certificados;
- aulas ao vivo;
- inteligência artificial;
- transmissão própria de vídeos;
- criação de uma plataforma de streaming.
Os vídeos serão cadastrados por links externos. O modelo de negócio poderá ser por assinatura, mas o pagamento não será processado dentro do sistema.
3. Usuários e funções
Todos poderão entrar pela web, mobile ou desktop. A diferença não será o dispositivo, mas a permissão do perfil.
Perfil	O que poderá fazer
Aluno	Criar conta, entrar, consultar cursos, matricular-se, estudar, acessar materiais, responder avaliações e acompanhar resultados e progresso
Mentor	Consultar alunos vinculados, acompanhar desempenho, visualizar avaliações e registrar orientações
Gestor	Administrar cursos, módulos, materiais e avaliações, além de consultar relatórios e indicadores
Administrador	Gerenciar usuários, perfis, permissões, situação das contas e controle geral do sistema


Separação importante
- O Gestor cuida da parte acadêmica.
- O Administrador cuida dos usuários e acessos.
- O Mentor acompanha o aluno.
- O Aluno consome os cursos.
Assim evitamos que Gestor e Administrador tenham exatamente a mesma função.

A regra principal será:
Web, mobile e desktop nunca acessam o SQL Server diretamente. Todos enviam solicitações para a API.

Exemplo:
1. O aluno clica em “Matricular-se”.
2. O site envia a solicitação para a API.
3. A API verifica o usuário e o curso.
4. A API grava a matrícula no SQL Server.
5. A API informa ao site que a matrícula foi realizada.

Autenticação final
O login deverá devolver:
- identificação do usuário;
- nome;
- perfil;
- token de acesso;
- mensagem de sucesso.
O token será como uma chave temporária. Ele permitirá que a API saiba:
- quem está fazendo a solicitação;
- qual é o perfil;
- quais funções essa pessoa pode acessar.
Não será suficiente esconder botões. A API também deverá bloquear funções proibidas.

TechLearnAcademy

Não será criada uma tabela separada chamada Alunos. Um aluno já será um registro da tabela Usuarios com:
Perfil = Aluno

O mesmo vale para Mentor, Gestor e Administrador.
Relacionamentos principais
- um curso possui vários módulos;
- um módulo pertence a um curso;
- um módulo possui vários materiais;
- um aluno pode ter várias matrículas;
- uma matrícula liga um aluno a um curso;
- uma avaliação possui várias questões;
- uma questão possui várias alternativas;
- somente uma alternativa será correta;
- um aluno pode realizar avaliações;
- o mentor acompanha alunos definidos;
- uma orientação pertence a um mentor e a um aluno.
Procedures obrigatórias
Para atender ao manual sem complicar:
- sp_RealizarMatricula: verifica e realiza a matrícula sem duplicação;
- sp_RelatorioCurso: devolve quantidade de alunos, média e aprovação.
Trigger obrigatório
Uma trigger poderá registrar na tabela de auditoria quando:
- o perfil de um usuário for alterado;
- uma conta for ativada ou desativada.
Isso é simples, útil e fácil de explicar na banca.

- MER;
- modelo lógico;
- modelo físico;
- dicionário de dados;
- chaves primárias;
- chaves estrangeiras;

9. Regras de negócio
1. Cada e-mail pertence a somente uma conta.
2. O cadastro público sempre cria um Aluno.
3. Somente o Administrador poderá transformar alguém em Mentor, Gestor ou Administrador.
4. A senha nunca será armazenada em texto puro.
5. A recuperação de senha terá código ou token com validade e uso único.
6. O usuário inativo não poderá entrar.
7. Somente o Gestor poderá alterar conteúdos acadêmicos.
8. Somente o Administrador poderá alterar perfil e situação dos usuários.
9. O Mentor visualizará apenas os alunos vinculados a ele.
10. O Aluno visualizará apenas seus próprios resultados.
11. Um módulo sempre pertencerá a um curso.
12. Um material sempre pertencerá a um módulo.
13. Um aluno não poderá ter duas matrículas ativas no mesmo curso.
14. Somente o aluno matriculado acessará os conteúdos e avaliações.
15. Cada avaliação terá questões objetivas.
16. Cada questão terá pelo menos duas alternativas e somente uma correta.
17. A nota será calculada na escala de 0 a 10.
18. O percentual será calculado pelos acertos divididos pelo total de questões.
19. A aprovação poderá utilizar o mínimo de 60%.
20. O progresso será calculado pelos módulos concluídos.
21. Vídeos serão cadastrados como links, sem streaming próprio.
22. Registros que já possuam relacionamentos serão desativados em vez de apagados.
